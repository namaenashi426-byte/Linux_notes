## 驱动程序

- **说明**：负责完成硬件初始化与配置，向上提供标准访问接口，并处理中断、DMA、并发、错误与电源管理等，保证字节流/事件能正确、安全地进出。

## 应用程序

- **说明**：负责整体业务逻辑，通过驱动提供的接口使用外设，不直接操作硬件。

## 文件描述符（fd）

- **说明**：Linux 系统中代表“打开的文件或 I/O 资源”的非负整数索引（int 型）。Linux “一切皆文件”，进程通过 fd 操作文件、管道、套接字、终端等资源。
- **回收**：程序退出前、或创建 fd 的函数返回前，必须用 `close(fd)`（`<unistd.h>`）释放。

## CMake

- **说明**：跨平台的构建系统生成器。只需写 `CMakeLists.txt` 描述项目，CMake 会自动生成 Makefile、Ninja、Visual Studio 等构建文件，再用 `cmake` 命令在构建目录里编译。

### 1. 最小可用框架

```cmake
cmake_minimum_required(VERSION 3.16)          # 要求 cmake 版本 ≥ 3.16

project(vehicle_app VERSION 0.1 LANGUAGES C)  # 项目名、版本、语言

set(CMAKE_C_STANDARD 11)                      # 使用 C11 标准
set(CMAKE_C_STANDARD_REQUIRED ON)             # 必须满足该标准
set(CMAKE_C_EXTENSIONS OFF)                   # 不用编译器扩展（即不用 gnu11）

# 生成可执行文件并指定源文件
add_executable(vehicle_app
    src/main.c
)
```

- **gnu11 开关**：删掉 `set(CMAKE_C_EXTENSIONS OFF)` 就允许 `-std=gnu11` 扩展；需要严格 C11 时保留本行。

### 2. 添加头文件查找目录

```cmake
# 把 src 加入 vehicle_app 的头文件搜索路径
# PRIVATE：只给 vehicle_app 这个目标用
target_include_directories(vehicle_app PRIVATE src)
```

- **引入方式**：建议统一写成 `#include "xxx/xxx.h"`（相对 `src` 的完整路径），避免同名头文件撞车。

### 3. 查找依赖库（必须写在 add_executable 之前）

```cmake
find_package(Threads REQUIRED)                  # 线程库
find_package(Qt5 COMPONENTS widgets REQUIRED)   # Qt5 的 widgets 组件
find_package(ALSA REQUIRED)                     # ALSA 音频库
```

- **顺序**：`find_package` 要放在 `add_executable` 之前，否则目标里拿不到库变量。

### 4. 链接库（写在 add_executable 之后）

```cmake
target_link_libraries(vehicle_ui PRIVATE
    Threads::Threads
    Qt5::Widgets
    asound
)
```

### 5. C / C++ 混合工程

#### 5.1 把共享代码做成静态库

```cmake
add_library(vehicle_core STATIC
    src/app/app.c
    src/hal/mock/vehicle_data.c
    src/services/settings.c
    src/services/log.c
    src/services/vehicle_warnings.c
    src/services/gps_service.c
    src/services/nmea.c
    src/services/gps_queue.c
    src/services/audio_mixer.c
)
```

- **适用场景**：C 与 C++ 都要用的模块，编译一次、两边链接。

#### 5.2 静态库声明自己的头文件目录与依赖

```cmake
# PUBLIC：任何链接了 vehicle_core 的目标，都会自动获得 src 这个头文件目录
target_include_directories(vehicle_core PUBLIC
    src
)

# PUBLIC：任何链接了 vehicle_core 的目标，都会自动连带链接下面这两个库
target_link_libraries(vehicle_core PUBLIC
    Threads::Threads
    asound
)
```

#### 5.3 分别生成 C / C++ 可执行文件

```cmake
# C 可执行文件
add_executable(vehicle_app
    src/main.c
)
target_link_libraries(vehicle_app PRIVATE
    vehicle_core
)

# C++ 可执行文件
add_executable(vehicle_ui
    src/ui/main.cpp
)
target_link_libraries(vehicle_ui PRIVATE
    vehicle_core
    Qt5::Widgets
)
```

### 6. 交叉编译工具链文件

- **用途**：一个目标板对应一个 `.cmake` 配置（如 `arm-linux-toolchain.cmake`），构建时用 `--toolchain` 指定。

```cmake
# 1. 告诉 CMake 正在交叉编译，并指定目标系统
set(CMAKE_SYSTEM_NAME Linux)              # 目标操作系统
set(CMAKE_SYSTEM_PROCESSOR arm)           # 目标架构

# 工具链根目录，后面用 ${} 展开
set(TOOLCHAIN_ROOT /home/namaenashi/100ask_imx6ull-sdk/ToolChain/arm-buildroot-linux-gnueabihf_sdk-buildroot)

# 2. 指定交叉编译器
set(CMAKE_C_COMPILER   ${TOOLCHAIN_ROOT}/bin/arm-buildroot-linux-gnueabihf-gcc)
set(CMAKE_CXX_COMPILER ${TOOLCHAIN_ROOT}/bin/arm-buildroot-linux-gnueabihf-g++)

# 3. 目标系统根目录（sysroot），保证头文件与库来自目标系统
set(CMAKE_SYSROOT ${TOOLCHAIN_ROOT}/arm-buildroot-linux-gnueabihf/sysroot)

# 4. 约束 find_xxx() 的搜索范围，避免误用宿主机的库和头文件
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)   # 程序在宿主机找
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)    # 库只在目标环境找
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)    # 头文件只在目标环境找
```

### 7. 构建命令

1. **生成构建文件**
   - `cmake -S <源码目录> -B <构建目录>`：`CMakeLists.txt` 必须放在源码目录
   - 简写 `cmake -B build`：以当前目录为源码目录，构建产物放进 `build/`
   - 交叉编译：追加 `--toolchain <工具链.cmake>`；若已有旧构建目录，先删掉再重新生成
2. **编译**
   - `cmake --build <构建目录>`
